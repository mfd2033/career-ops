# ADR-0080: 跟进话术模板库——`templates/followup-scripts.md` 与 LogDialog「生成话术」（career-ops-50）

## 状态

Accepted (2026-10-16)

## 背景

需求（Kaneo 任务 career-ops-50）：跟进话术是核心资产——**三句话结构（事实＋意向＋下一步）**，纪律是「售前先问出差 ≤30%，不问不聊」「同公司别三连发」——目前散在「话术与纪律」sheet 和各期行动清单里，无法复用、无法机读。

任务原文两步：第一步建 `templates/followup-scripts.md`（7 条结构化：模板名／适用场景／正文／占位符，`{投递日}{岗位名}` 从 tracker 行自动取）；第二步 LogDialog 加「生成话术」（按轮次选模板、占位符自动填、一键复制）。**用户 2026-10-16 决定：两步一起做。**

既有事实与约束：

1. **零新增写面**：复制只进剪贴板——用户在猎聘 App 自己粘贴发送。`AGENTS.md` 的伦理红线（永不代替用户发送）在本需求里不是建议而是设计边界。用户明确「**不联动**」：不回填备注、不写 `data/follow-ups.md`。
2. **占位符需要的数据全在既有入口里**：LogDialog（ADR-0075 原样复用）已持有 `CadenceEntry`——`appliedDate` / `role` / `num` / `company` / `daysSinceApplication` / `followupCount` / `followups[]`。**无需新读取路径**，也不新增后端字段。
3. **server helper 已有单点**：`web/src/lib/followups-server.ts` 的 `readCadencePayload()` / `readFollowupEntry(id)` 是 cadence 判定的唯一读取实现（ADR-0075 决议 7）。本需求的填充走同一份 entry，不另起一份装配。
4. **可测性约束同 ADR-0079 决策 7**：组件无测试面；模板解析与占位符填充必须抽到纯 `.mjs`，用 `node --test` 门住，路由 `.ts` 无法被裸 node 导入。
5. **视觉方案已原型定稿**：三个布局原型（①弹窗内展开／②加宽左右分栏／③独立右侧抽屉）已渲染给用户逐案比对，**用户选定方案 ①**。
6. **7 条正文是草稿**：4 条种子（首轮跟进／二轮保岗／售前问出差／留档各一）来自原型，另 3 条按同结构补齐；正文由用户后续改写，本 ADR 只锁**结构**。

## 决策

1. **文件格式 = 行式严格 markdown**，`templates/followup-scripts.md`（路径按任务原文）：`## 模板名` 为一条话术的开始，正文四条 `- 分组: / - 场景: / - 事实: / - 意向: / - 下一步:`，分组取值限于四桶（`首轮跟进`／`二轮保岗`／`售前问出差`／`留档`）。文件头用文字声明占位符白名单。选 `.md` 的理由：同**一份**文件既要给人读（行动清单生成）又要给机器读（web），行式格式解析器只有十几行，且改正文不需要动代码。
2. **占位符分两类**：**自动**（`{投递日}`←`appliedDate`、`{岗位名}`←`role`、`{编号}`←`num`、`{公司名}`←`company`、`{天数}`←`daysSinceApplication`、`{上次跟进日}`←最近一条 `followups[].date`、`{跟进次数}`←`followupCount`）与**手填**（`{城市}`／`{原因}`／`{时间}`，无数据源）。白名单是纯模块里的常量，解析器把白名单外的键也一并收集，供 UI 与测试断言。
3. **解析与填充在纯模块 `web/src/lib/followup-scripts.mjs`**：`parseScripts(md)` → `{name, group, scenario, lines:{fact,intent,next}, placeholders}`；`fillScript(script, row)` 按映射替换，**取不到值或不在映射表里的占位符原样保留 `{key}`**——不静默清空，不猜。缺值列表随结果返回，UI 据此标出「复制后你自己补」。
4. **web 读取经 API，不在客户端碰文件系统**：`GET /api/followups/scripts?num=N` → server 端读模板文件 + 用 `readFollowupEntry(N)` 的同一份 cadence entry 填充，返回 filled 结果；文件缺失／引擎不可用一律 fail-closed 成 `{available:false}`（同 `/api/followups` 的既有形状）。客户端只渲染，不复算、不读文件。
5. **UI = 方案 ①（弹窗内展开）**：`log-dialog.tsx` 底部新增可折叠「生成话术」区，**默认收起**；展开后自上而下：纪律轨（三句话＋售前先问出差＋同公司别三连发）→ **分组 chips**（4 枚，即原型已批准的外观）→ **组内变体 chips**（仅当该组 ≥2 条时渲染）→ 占位符来源一行说明 → 三行结构正文（左栏 mono 标签 `事实/意向/下一步`）→ 「复制话术」＋「系统只生成，不代发」。7 条话术仍按四个场景桶组织：**一级选轮次、二级选变体**，正文区标题行显示「分组 · 模板名」。
6. **复制语义 = 剪贴板单向**：`navigator.clipboard.writeText(三句话换行拼接)`；失败回落 `Range` 选中 + 「已选中，按 Ctrl+C」。**不写备注、不写 `data/follow-ups.md`、不调任何写接口**（用户决策「不联动」）。
7. **文案进 i18n，数据不进**：新增键全部落 `web/src/lib/i18n/clusters/followups.ts`（en+zh）。**7 条话术正文是用户中文资产，不进 i18n**——它是数据，不是界面文案；i18n 只覆盖区块标题、纪律轨、分组名、按钮与说明句。

## 被拒方案

- **加宽弹窗左右分栏**（原型 ②，否决）：弹窗从 28rem 破到 52rem，移动端要整套重排，换取的主要收益是「弹窗不变高」——而弹窗变高只是滚动，代价与收益不成比例；并破 ADR-0075「原样复用 LogDialog」的宽度约定。
- **独立右侧抽屉**（原型 ③，否决）：记录弹窗一字不改是优点，但必须新增一个弹层、一套焦点陷阱、Esc 归属与层级管理，测试面跟着变大；ADR-0075 的「单一弹窗」边界被打破。
- **YAML 数据文件**（否决）：任务原文指定 `.md`，且同一份文件要给人读；行式 markdown 同时满足人与机器，多写一份 YAML 就要多一份同步纪律。
- **另存一份 JSON 副本给 web**（否决）：第二份数据源＝漂移缺陷类，同 ADR-0079「web 侧复算 freezeSuggested」的否决理由。
- **客户端直接读 `templates/` 文件**（否决）：浏览器拿不到仓库文件；必须经 server helper（同类边界见 `web/src/lib/core/normalize-text-key.mjs` 的「declared copy」注释）。
- **复制顺带回填备注 / 写 `follow-ups.md`**（否决）：静默替用户记录陈述，是替用户说话的写路径——同 ADR-0079 拒掉的「预填原因直接落 notes 不经用户」。
- **一键发送 / 打开猎聘 App 预填**（否决）：`AGENTS.md` 伦理红线，用户必须自己粘、自己发。
- **7 条扁平 chips（否决）**：四个场景桶是任务自己的词汇与已批准的原型外观；扁平化会把「轮次」语义压成 7 个平级按钮，模板增加后不可扩展。

## 后果

- 正面：话术从散落 sheet 变成单一可机读资产，CLI 行动清单与 web 记跟进喂**同一份**文件；写面零新增；判定与填充逻辑集中在可测的纯模块里。
- 代价一：`templates/` 在 `DATA_CONTRACT.md` 里名义属 System Layer（可能被系统更新覆盖），而本文件内容是用户个人资产 → **实体上按用户层对待**：不得被系统更新覆盖，纳入数据层影子备份白名单（与 `data/` 同级）。
- 代价二：正文为草稿（4 条种子 + 3 条补齐），用户改写前不应被当成定稿口径；解析器对未知键保留原样，改内容不需要动代码。
- 已知边界：`{城市}`／`{原因}`／`{时间}` 永远手填——复制文本里保留花括号是刻意的提示，不是缺陷；`{上次跟进日}` 在无跟进记录时取不到值，该句按「待补」显示。
- 回滚：删该文件 + 撤 UI 增量即回到现状；纯增量，无数据迁移。
