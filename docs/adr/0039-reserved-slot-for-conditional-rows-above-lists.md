# ADR-0039: 列表之上的条件行改建常驻槽位（批量条不再顶开列表）

- **Status:** Accepted (2026-09-18)
- **Context:** 用户报（2026-09-18）：管道「已评估」页批量勾选时「忽然出现一行，列表往下移动」。根因是 ADR-0011 的定高布局与条件渲染的交互——顶区元素一律 `md:shrink-0`、列表容器 `md:flex-1 md:min-h-0`，于是**任何顶区行的出现/消失都直接改变列表容器的高度与顶边位置**：`pipeline-view.tsx` 的批量条（`selected.size > 0` 才渲染，位于 tabs 与表格容器之间）一出现，表格容器顶部下移，可视行整体下滑；`inbox-triage.tsx` 的多选条（同款条件渲染 + `md:shrink-0`）同因同形。清单核对：`web/src/components` 下带 `md:shrink-0` 的顶区元素只有上述两处批量条，外加管道页「分数 ≥ N」筛选条（`minFilter != null` 才渲染，点它的 X 清除时列表上跳）——「查看全部 N 项」按钮虽然也条件渲染，但那是「展开列表」动作本身，不在本类。
  1. **ADR-0011 只约束了「不压缩」，没约束「不出现/不消失」**：`md:shrink-0` 保证顶区元素不被压缩，但条件行的挂载/卸载仍是一次净高度变化。本次不是推翻 ADR-0011，而是把它缺的那半条补上。
  2. **移动端没有定高布局**：`md:` 以下 `/pipeline` 是整页自然滚动（ADR-0011 决议 3），槽位若在手机上也常驻，代价是选中态两条按钮行（每行 44px 触控高）+ 内边距 ≈ 108px 常驻空白，占 iPhone 844 视口约 13%，而手机上看批量动作是次要路径。
  3. **槽位高度必须按选中态锁定**：条内的文案在选中期间还会变（`selectedOffView` 的「N 项在当前筛选之外」出现、`urlMapLoading` 的「正在解析职位链接…」被「N 项中有 M 项含职位链接」替换、按钮计数随勾选变化），条本身是 `flex-wrap`，任一处折行都会让列表再跳一次。
  4. **探索页已是不跳的形态**：结果区把「加入管道 (N)」做成常驻按钮、无选中即禁用（`results-list.tsx`），可作参照；收件箱的 `ShortlistTray` 则是「底部悬浮」形态的先例。

- **Scope:** web 层——新增常驻槽位容器 `web/src/components/row-slot.tsx`；`pipeline-view.tsx` 接入槽位（含空态提示语、锁单行、分数筛选 chip 归入 tabs 行）；`inbox-triage.tsx` 接入槽位；i18n 三键；`CONTEXT.md` 立「批量条」词条；ADR-0011 补延伸指向与用词统一。**不动**：ADR-0011 的定高布局本身、`md:shrink-0` 语义、`orderApplications`/`countSelectedOffView` 等纯逻辑、选中集语义（仍以 `r.n` 为键、跨 tab 保留，ADR-0038）、`ShortlistTray` 与 undo toast 的位置、`inbox-triage.tsx` 的「查看全部 N 项」按钮。

## Decision

1. **列表之上直接相邻的条件行一律常驻槽位**：槽位在 tabs 与列表容器之间恒在，只切换内容，不改变自身高度。新的条件行不得再以「挂载/卸载」的方式影响列表——要么进槽位，要么进某个本就常驻的行。
2. **槽位只在 `md:` 及以上存在**（与 ADR-0011 的定高断点同界）：定高布局在哪一档生效，槽位就在哪一档生效。`md:` 以下维持现状（条出现时把列表下推），**记为已知残差**而非缺陷遗漏。
3. **槽位高度按选中态写死、内容锁单行**：管道槽位 `md:h-9`、收件箱槽位 `md:h-10`；条在桌面端 `md:flex-nowrap`，提示文本 `truncate`，槽位 `md:overflow-hidden`——选中数变化、链接解析中→完成、屏幕外计数出现，均不改变高度。窄屏保持 `flex-wrap`（那里本就不锁高）。
4. **空态放一句淡提示语**，不做空白占位、也不做灰化禁用按钮条：占位本身要说清这一步能做什么，且与刚点过的表头全选框相邻。文案按页写各自的动词——管道「勾选行后可批量重新评估[或跳过]」（已评估 tab 多「或跳过」，其他 tab 只说重新评估，与 ADR-0038 决议 2 的按钮可见性对齐）；收件箱「勾选岗位后可批量存入短名单或跳过」。
5. **小 chip 归入本就常驻的行，不占独立行**：管道的「分数 ≥ N」筛选条从独立行移进 tabs 行右侧（带边框的 chip 形态不变）。**实测残差**（bsk，1218px 视口、侧栏占 240px 后内容宽约 930px）：11 个 tab 已把 tabs 行顶到折行边界，chip 一出现行高 34px→64px，点 X 清除时列表整体上移 30px——这类残差**不限于窄屏**，凡 tabs 行处于折行边界的宽度都会发生。接受理由：`minFilter` 的变化多伴随导航（首页分数链接进入）、清除是低频动作，且不属于本次报的场景；消除方案见 Alternatives 的常驻占位。
6. **INBOX tab 不占槽位**：管道页槽位只属于非 INBOX tab（收件箱由 `InboxTriage` 自己那套负责，含它自己的槽位与提示语）。跨 tab 切到 INBOX 会少一行高度，但切 tab 本就是整块换内容，不属本类。
7. **只抽槽位容器，不抽完整批量条组件**：`row-slot.tsx` 只负责「常驻 + 断点定高 + 空态回退」，内容由两个调用方各自给。两处的文本与动作差异不小，配置化的完整组件是过早抽象。
8. **验证用 bsk 量几何**，不用 Playwright：`bsk evaluate` 可直接取首行与表格容器顶部的 `getBoundingClientRect`，勾选前后断言 y 不变，验的正是用户在跑的那份构建；`bsk emulate --device iphone-14` 只用于确认窄屏行为与改前一致（第 2 条已决定不动它）。仓库内一次性 qa 脚本（Playwright）不是本决议的验收方式。

## Alternatives considered

- **底部悬浮条**（学 `ShortlistTray` 的 `fixed inset-x-0 bottom-0 sm:bottom-4`）：同样零位移且不占高度，但遮住末几行，还要与 sticky thead（z-10）、托盘（z-30）、undo toast（z-40）协调层级；更重要的是它把行动点搬到远离「全选」复选框的地方。用户已选常驻槽位。
- **并入 tabs 行**（把动作塞进本就常驻的 tabs 行右侧）：零位移且不新增高度，但横向空间窄，桌面端按钮+三段提示根本放不下，窄屏必然折行。用于小 chip（决议 5）合适，用于批量条不合适。
- **抽完整批量条组件**：单实现、第三处直接复用，但两处内容差异（三段提示、链接解析态 vs 纯计数）会逼出一套配置面，收益不抵抽象成本。用户已选只抽容器。
- **移动端也常驻两行（约 108px）**：手机零位移，但永久吃掉约 13% 视口高度，而那段地方平时只放一句提示。用户已选移动端维持现状。
- **移动端改底部悬浮 / 条渲染在列表末尾**：前者要引入第二套机制，后者在长列表里让动作离勾选位置太远。均已讨论并否决（用户选「移动端不处理」）。
- **Playwright 几何断言**：可留在仓库里重跑，但本机 web 只装了 `playwright-core`、与 `ms-playwright` 缓存里 chromium-1234 的配对未验证；位移是一次性验证的性质，不值得为此引入浏览器测试链路。用户已选 bsk。
- **给筛选 chip 常驻占位**（tabs 行里放一个 `invisible` 的同宽占位，让折行判定与 chip 在否无关）：能消除决议 5 实测到的 30px 残差，但边界宽度上会把「偶发两行」变成「常驻两行」，且占位宽度是随文案/字号漂移的猜出来的常量；低频动作的 30px 位移不值这个代价，暂不采用。

## Consequences

- 桌面端 `/pipeline`（非 INBOX tab）与收件箱：勾选、取消勾选、清空选择、链接解析态变化都不再挪动列表。
- 代价：桌面端常驻一行空白（管道约 36px、收件箱约 40px），空态由一句淡提示语填充。
- 两处已记档的已知残差：①`md:` 以下批量条依旧会把列表下推（决议 2；**用户 2026-09-18 确认不在手机等移动端使用，不再考虑**）；②tabs 行处于折行边界宽度时（实测 1218px 视口、约 930px 内容宽），筛选 chip 的出现/清除会让列表下/上移 30px（决议 5）。
- 槽位只覆盖「列表之上直接相邻」的条件行；`inbox-triage.tsx` 的「查看全部 N 项」不在内（展开动作本身改变列表）。
- 新增一条界面规则：往顶区加条件行前先问「它会不会挪列表」——要挪就进槽位。
- 槽位高度是写死的常量（`md:h-9` / `md:h-10`），与条内边距耦合；日后改条的内边距要同步改槽位高度，否则又会开始跳。
