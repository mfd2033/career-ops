# ADR-0024: 收件箱默认激活「未评分」过滤与「按薪资」排序

- **Status:** Accepted (2026-09-14)
- **Context:** ADR-0010 以「新鲜小批次（fresh batch，默认截断 20 条）」为收件箱默认视图，ADR-0023 决定 4 明确「按薪资排序关 = 默认新鲜度」。用户在实际 triage 中每次进页面都要手动点亮「未评分」和「按薪资」，两个默认从未被用到——要求把两者改为默认激活。这正面推翻两条 ADR 的明文默认值，故独立成文（旧 ADR 不改写，本文覆盖其默认值部分）。

## Decision

2026-09-14 逐条确认的五条：

1. **默认激活，持久化对称**：`unscoredOnly` 与 `sortBySalary` 初始均为开；两者都走 localStorage（未评分新增 `career-ops:inbox-unscored` 键）。无记录时用默认开；用户手动关掉后每次加载保持关。「默认」只是无记录时的初值。
2. **接受全量墙**：默认开未评分 → `anyFacet` 恒真 → 列表不再截断（BATCH 20 的 fresh-batch 默认退役）。贴合 ADR-0010 本意的「只看未评分 → 全选 → 批量」流；全选本就作用于全部过滤结果，不截断更诚实。
3. **空态不加逻辑**：全部评完后默认视图就是「无匹配 / 放宽过滤」空卡片，接受，不做自动回退或切换入口。
4. **并列 tie-break 回退新鲜度**：按薪资排序时，中位值相等（含双未知）一律回退新鲜度——排序语义一条规则说完：先中位值降序，平手与未知都回新鲜度；不依赖 `Array.sort` 稳定性这类隐含实现细节。
5. **「清空」= 回到默认**：`onClear` 把未评分、按薪资重置为开，其余条件清零。否则清空后会意外落入已废弃的 fresh-batch 截断视图。头部文案沿用「N 条匹配」，不为默认态新增 i18n 键。

## Consequences

- **新鲜度降级为回退策略与「关」态**：SINGLE ORDER PLUG POINT 的默认比较器从新鲜度变为按薪资降序；新鲜度只在用户关闭排序、薪资平手、双未知三种情形出现。
- **薪资未知行默认沉底**：旧行 / 手写 note 的行（无尾段薪资）在新默认下永远沉在列表底部——ADR-0023 已按「薪资未知」语义接受，此处仅是默认可见化。
- **fresh-batch 截断成为死代码路径**：`capped` 只在用户把两个开关都手动关掉后出现。暂不删除，保留「关开关回到小批次」这条退路。
- **「清空」会覆盖持久化的开关偏好**：清空后两开关回到开并被持久化——用户重启后偏好已被清空动作改写。这是「清空 = 初始化状态」语义的接受代价。
