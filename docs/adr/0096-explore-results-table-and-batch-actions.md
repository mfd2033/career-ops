# ADR-0096: 探索页结果区的表格化、过滤与批量处置

- **Status:** Accepted (2026-10-30 ~ 2026-11-03)，**回填记录**（2026-11-03 补写）
- **回填说明：** 本 ADR 记录的是**已经落地**的一组决策。它的诱因是一场审查：
  `docs/REVIEWING.md` 规则 3 要求「>200 行的改动必须有工单可对照」，而这一批提交
  （结果区表格化、标签条、薪资下限、拉黑所选/行内拉黑、评估所选、标题门弹窗化）
  进仓库时既无 ADR 也无工单，只有 commit message 自述——审查时无法判断「代码是否
  忠实实现了当初的意图」，只能判断「代码与它自己的 commit message 一致」。下面的
  rationale 是从代码注释、commit message 与既定 ADR 反推的，不是事后发明的新理由。

- **Context:** 探索页结果区原本是**卡片网格**：每张卡片自带标题/公司/地点/来源/薪资
  与本行动作。它撑不住这个页面后来长出来的用法：

  1. **薪资无法横向比较**。卡片是纵向流，薪资散落在每张卡的副行里，「哪家给得多」
     要靠眼睛在卡片之间来回找。
  2. **没有批量入口**。想评估 20 条得点 20 次；想一次拉黑一类岗位，只能逐条操作，
     或者绕去标题门里手工抄词。
  3. **勾选语义散在两处**。「全选可加入 (N)」的计数来自整个结果集，而屏幕上的行
     来自 tab+关键词过滤后的列表（`results-view.mjs` 头注释记录的原缺陷）——输入
     关键词后按钮承诺 N 条、屏上只有 3 条，点下去还确认了看不见的行。
  4. **标题门词表编辑是内联的**，把整块配置摊在结果区里：翻到词表底部才看得见保存
     按钮，等于逼用户先滚一遍。
  5. **词表是活的，扫描记录是死的**。采集时被放行的行，在用户改完词表之后其实该被
     毙掉，但扫描记录里只有采集那一刻的判定。

- **Scope:** `web/src/components/explore/*`（`results-list.tsx`/`discovery-card.tsx`/
  `gate-panel.tsx`/`tag-bar.tsx`/`explorer-view.tsx`/`explore-provider.tsx`）、
  `web/src/lib/{results-view,result-tags,row-click,deny-words,whats-new-filter}.mjs`、
  `web/src/app/api/whats-new/route.ts`、`web/src/lib/i18n/clusters/explore.ts`。
  **不动**：采集器与扫描器（`scan.mjs` 一族）、`portals.yml` 的写入语义（沿用
  `/api/portals/title-filter`）、追踪表结构、收件箱的 facet 实现（只借交互口径）。

## Decision

1. **结果区改为表格**：列为「勾选 / 职位 / 薪资 / 来源 / 操作」，窄屏横向滚动；
   表头承担全选（三态复选框，半选点击 = 全选，与管道页表头同款口径）。全选入口
   从工具栏按钮收进表头，动作条只留批量动作。
2. **整行可点切换勾选**，勾选只对「未入管、未评估、本次未加入」的行开放
   （`isSelectable`）；表头全选与清除都**只动屏幕上可见的那批**——屏幕外的勾选等它
   重新可见时再处置，不在过滤变化时被无声抹掉。
3. **列按决策需要裁**：公司/地点列与外链图标移除（信息已在标题副行里），薪资列左移
   到来源左侧；**排序切换器移除**——结果集顺序就是采集顺序，多一个视图的维护成本
   高于收益。
4. **标签过滤条零 token**：词表由服务端给（与收件箱关键词条同一份，ADR-0068），
   客户端做匹配。**chip 上的计数基底是薪资过滤后的集合**，保证「chip 数字 = 点击后
   匹配条数」这句话对屏上这批成立。
5. **薪资下限是展示过滤，语义刻意与采集门不同**：严格下限（区间下界 ≥ 输入值），
   无薪资/解析失败的行走人；采集门则是「区间重叠 + 未知放行」。理由：采集门回答
   「谁**可能**给得到」，宁可多收；展示过滤回答「谁**确实**给得到」，留下一条
   「筛 ≥20K 却显示 15-25K」的行在屏上就是 bug。默认关（0 = 不过滤），不进 URL、
   不跨搜索保留。
6. **拉黑所选 / 行内拉黑是同一条回路**：`suggestDenyWords` 从勾选（或那一行）的标题
   推出候选词 → 带入标题门弹窗的草稿 → **保存只发生在弹窗里**。工具栏与行内按钮都
   不写任何文件，因此不存在第二条写路径。行内按钮只在浏览器板路径（`isBsk`）渲染：
   ATS 路径没有标题门。
7. **评估所选 (N) 与「加入管道」取同一集合**（`selectedAddable`）。勾选本来就只对
   未入管/未评估的行开放，所以这个集合天然不会重复评估。1 条走 `/api/run` 单任务
   （与行内评估完全同路）；多条按 `EVAL_BATCH_MAX` 切块走 `batch-evaluate`——只有
   它一次预留连续报告号并由编排器统一 merge，才敢并发；超过阈值先落一次二次确认；
   派发后立即清勾，避免下一次点按把同一批 URL 再派一遍。
8. **标题门编辑改为弹窗（「过滤配置」）**：固定头尾、滚动收在窗口内；**关闭即放弃**
   未保存改动（弹窗里没有「暂存」语义，X/遮罩/Esc 一律复位）；词条可就地改名、与
   已有词重名当场拒绝；保存前**试算**（会放行 N 条 / 会多毙 N 条）并预览标题；
   「拉黑」带入的新词在弹窗里高亮，删掉其中一个只熄灭它自己。
9. **今日页「本周新匹配」用当前词表重判**：扫描记录的 `status` 只反映采集那一刻的
   判定，词表是活的，所以 `/api/whats-new` 用当前编译出的门（`buildTitleFilterExplained`
   ——与探索页结果区、两路采集 driver 同一份实现）对每条台账行重判；`portals.yml`
   缺失/损坏时**不门控**（全部放行），与「扫描不因配置坏掉而全空」同一取舍。
10. **刷新首帧不闪，且不逐条重算**：首帧直接回灌 sessionStorage 里的上次结果集
    （不再先闪配置页/探索中）；追踪表的归一化改为**按结果集算一次的预归一索引**
    （`buildEvaluationIndex`，743 行一次，而不是 200×743 次 `new URL()`），
    `evaluatedNoFor` 本体也委托到索引版——两个入口永不漂移。
11. **批量条动作常显**：移除/拉黑不再靠 hover 才出现；计数与动作按**可见勾选**收窄，
    避免「计数 12、实际只处置 3 条」的错位。

## Alternatives considered

- **保留卡片网格，加一栏并排**：卡片是纵向流，薪资永远对不齐，「一眼比薪资」这件事
  只有表格能给；否决。
- **全选沿用工具栏按钮**：按钮是「结果集的全选」，表格是「屏幕上的全选」，两者同屏
  必然再次分叉（`results-view.mjs` 记录过一次）；收进表头，让勾选态与可见集合同源。
- **薪资过滤沿用采集门的区间重叠**：实现成本为零，但屏上会出现「筛 ≥20K 留下 15-25K」
  的行，读起来是 bug；宁可严格、宁可隐藏无数据的行。
- **拉黑直接写 `portals.yml`**：一步到位，但绕开了「草稿 → 试算 → 确认」的回路，等于
  给用户一条无预览的写通道，并且自带第二套写路径（ADR-0084 的黑名单门禁回路同理）；
  否决。
- **保留排序切换器**：结果集顺序即采集顺序，多一个视图只增加「切完看到什么」的解释
  成本；移除。
- **今日页不做重判**：省掉一次门编译，但用户改完词表回到今日页会看到本该被毙的岗位；
  重判比「解释为什么它还在」便宜。

## Consequences

- 结果区的判定全部下沉到纯函数模块（`results-view.mjs` / `result-tags.mjs` /
  `row-click.mjs` / `deny-words.mjs`），组件只负责渲染与派发，可由 `node --test`
  锁定；这也让「按钮数字 / 勾选框 / 实际处置的行」三者同源成为可断言的事。
- **已知代价**：标签 chip 的计数基底是薪资过滤后的集合，改派生链时必须同步 wiring
  断言。2026-10-30 漏过一次（`result-tags.test.mjs` 仍钉着旧的 `tagScope`），
  教训写在测试里：改派生链要同时看 `results-view.test.mjs` 与 `result-tags.test.mjs`。
- 两条采集路径的可用动作不同是刻意的：ATS 结果没有标题门，因而没有拉黑/过滤配置；
  差别写在渲染条件里，不做「看起来一样但点了没用」的统一。
- 被移除/被跳过的行只存在于展示态（sessionStorage 快照），不写 `pipeline.md`；
  刷新后仍隐藏。
- 未覆盖：结果区没有排序；薪资过滤不跨搜索保留；大批量评估的报告号区间仍然由
  服务端按块各预留一次（不是一整段连续号）。
