# ADR-0067: 数据分析页下钻跳转（阶段/分数区间/公司 → 求职管道）

- **Status:** Accepted (2026-09-26)
- **Context:** 需求（2026-09-26 grill 会话，三轮问答全部锁定）：「web 端，数据分析页面，点击数据可以跳转到求职管道页面，展示对应的数据列表」。现状与约束：

  1. **管道页的 URL 上下文只有五个参数**（`tab/min/q/sort/dir`），过滤与排序住在 `pipeline-order.mjs` 这个单一事实源里，列表页与报告详情页的 prev/next（ADR-0036）共用同一套 `normalizeContext` / 比较器与 `buildContextQuery` 序列化——任何新维度必须整条链路进上下文，否则「列表所见」与「导航所走」会漂。
  2. **分析页四类数字的口径各不相同**：阶段条形按 `canonStatus(status).includes(key)` 计数（与 tab 过滤同构，天然可精确表达）；分数桶按半开区间 `[下限, 上限)` 且只数有效分数；Top 公司按 `a.company` 原始字符串用 Map 精确分组；头条面试/offer 两枚是 **ever 累计**（`cumulativeTiles`，"曾经到达过"），管道 tab 只表达当前状态——这一组无论怎么跳数字都必然对不上。
  3. **管道现有参数表达不了两个维度**：`min` 只有下限（4.0–4.4 桶会混入 4.5+ 的行）；`q` 是公司+职位的模糊子串（公司跳转的列表行数会 ≥ 条形数字）。
  4. **tabs 行已有可清除 chip 先例**（ADR-0039 决议 5）：`min` 筛选渲染为「分数 ≥ x ✕」chip 住进 tabs 行，卸载不引起列表跳动——新维度照此视觉语言，不另发明控件。
  5. **管道页无参数时默认落 INBOX**（triage 队列，没有 tracker 行可显示）——凡是想让用户看到过滤列表的深链都必须显式带 `tab=`。

- **Scope:** web 层五处——`pipeline-order.mjs`（`max`/`company` 过滤 + 上下文序列化）、`pipeline-view.tsx`（URL 解析 + 新 chip）、`pipeline/[id]/page.tsx`（`parseContext` 补两个参数）、`analytics/page.tsx` + `analytics-view.tsx`（条形行变下钻链接）、i18n 新键。**不动**：头条统计卡的跳转（明确不做）、ever 累计过滤语义、排序键（`SORT_KEYS` 双镜像不改）、assistant 的 `filterPipeline` action 参数集（`navigate` 本就接受任意 query string，够用）、数据层任何文件。

## Decision

1. **三组条形整行可点下钻，四枚头条统计不跳**：管道阶段条形 → `?tab={状态}`；分数分布桶 → `?tab=ALL&min=&max=`；Top 公司 → `?tab=ALL&company=`。头条面试/offer 是 ever 累计语义，与管道 tab 的当前状态语义必然数字不一致，跳了反而误导，故不跳（总数/平均分是全局标量，无可过滤对象）。
2. **严格计数一致是本品类的核心约束**：跳转落地后管道列表行数必须等于分析页条形上的数字。为此管道新增两个 URL 参数：
   - `max`——分数上限，与 `min` 组成**半开区间 `[min, max)`**（与分析页桶的 `>= && <` 完全同构）；无效分数（NaN/缺分）行被排除，与分析桶只数有效分数同口径。单独 `max`（如 `< 3.0` 桶）与单独 `min`（如 `4.5–5.0` 桶）都是合法形态。
   - `company`——与 `a.company` 原始字符串**全等**匹配（区分大小写、不做 trim 之外的加工），与分析页 Map 分组同一口径；大小写不敏感或子串匹配都会让行数 > 条形数字，破坏决议 2。匿名雇主 `?` 行按字面 `?` 匹配，天然工作。
3. **新参数进入共享上下文全链路**：`normalizeContext` 补 `max`（数值或 null）与 `company`（字符串或空）字段；`orderApplications` 增加两个过滤步骤；`buildContextQuery` 序列化（非法/缺省值一律省略，落地端 fall back 为无该筛选——与 `min` 现有姿态一致）；详情页 `parseContext` 解析后喂 `navNeighbors`。列表行链接、prev/next、返回链接因此自动 reproduce 同一上下文，无需新机制。
4. **落地上下文由链接自带，不做跨页记忆**：分数桶与公司跳转固定显式携带 `tab=ALL`（否则落 INBOX 空列表）；阶段跳转只带 `tab=状态`，不附带其它维度。排序沿用默认（score 降序，URL 省略）。
5. **分数是一个维度、一枚 chip**：无 `max` 时维持现状「分数 ≥ x ✕」（只清 min，首页统计卡深链行为不变）；有 `max` 时渲染单枚区间 chip——双端「分数 4.0–4.5 ✕」、仅上限「分数 < 3.0 ✕」——清除时 min 与 max 一起清。公司另独立一枚「公司: xxx ✕」chip。两枚 chip 与搜索框 `q` 共存为 AND 叠加。chip 住 tabs 行，遵循 ADR-0039 决议 5 的不跳位纪律。
6. **分析页交互形态**：`n = 0` 的条形行不可点（无链接、无 hover 效果，避免跳到空列表的死交互）；可点行 hover 背景微亮 + 标签变链接色 + 原生 `title` tooltip（zh「在管道中查看这 N 条」）；实现为整行包一层 `<Link>`，键盘可聚焦回车跳转，与管道列表公司列行链接（ADR-0062 单导航入口）的无障碍姿态一致。分析页 href 全部经 `buildContextQuery` 生成——URL 上下文形状只定义一次，分析页与管道页不可能序列化出两种写法。
7. **i18n**：tooltip 与 chip 新键双语句对（en/zh），用户可见文案简体中文。分数区间 chip 文案把边界格式化为一位小数（与桶标签一致），公司名原样显示不翻译。

## Alternatives considered

- **专用 `bucket=4.0-4.5` 参数**：只服务分析页跳转，无法与手动 `min` 筛选组合，管道页多出一套只读概念——被通用上下文的取向否决。
- **近似复用现有参数**（桶跳 `min` 下限、公司跳 `q`）：零新增参数、改动最小，但列表行数 ≠ 分析页数字，用户会把差额当数据 bug——被决议 2 的严格一致否决。
- **头条 ever 卡也跳（tab=INTERVIEW）**：数字必不一致（曾经面试 ⊇ 当前面试），是三口径中最容易骗到人的跳法。
- **继承用户上次管道视图**（跨页记忆 tab/sort）：需要新增跨页面状态，行为不可预测，收益只是"少一个参数"。
- **公司筛选塞进搜索框 `q`**：视觉省一枚 chip，但模糊匹配破坏严格一致，且污染用户自己的搜索词。
- **仅数字可点 / 悬停箭头图标**：点击目标小、可发现性差，整行可点在移动端口径上占优。

## Consequences

- **URL 上下文从五参数长到七参数**：`/pipeline/{n}?…` 深链多两种要吃的参数；非法值（`max=abc`、`company=` 空）一律降级为"无该筛选"而不是报错——`normalizeContext` 的既有形状保证这一点。
- **一致性从"约定"升级为"共享表达式"**：分析页数字与管道行数同源的前提是两边都走同一过滤式；未来任何一侧改口径（比如分析桶改成闭区间）都必须同步另一侧，由 `pipeline-order.test.mjs` 的 max/company 用例与下钻 href 用例兜底。
- **`buildContextQuery` 成为分析页的依赖**：analytics page 从纯服务端计数页变成共享过滤模块的消费者——这是收拢而非耦合：宁可多一个 import，不要第二份 URL 拼接。
- **首页统计卡深链行为不变**（决议 5 显式保护）：它们只带 `min`，渲染仍是「分数 ≥ x」chip、清除仍只清 min。
- **明说的不做**：分析页跳出不意味着管道页获得"分析视图回链"；头条卡将来若要跳，需要先给管道定义 ever 累计过滤（一个新概念，独立 ADR）。
