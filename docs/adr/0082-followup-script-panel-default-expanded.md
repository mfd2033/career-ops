# ADR-0082: 「生成话术」面板默认展开

## 状态

Accepted (2026-10-16)

## 背景

需求（用户 2026-10-16，原话）：「默认展开生成话术面板」。

现状：ADR-0080 把「生成话术」设计成 LogDialog 底部**默认收起**的可折叠区——理由是它是一块可选内容，别喧宾夺主。ADR-0081 给它加了「打开职位」，动作行成为 复制话术 → 打开职位 → 粘贴 → 发送 闭环的起点。此时收起态反而挡在闭环前面：用户每次打开「记录跟进」都要先点一次折叠标题，才看得到话术与那两颗按钮。

## 决策

1. **默认展开**：`GenerateScriptPanel` 初始态 `open = true`（`useState(true)`）。
2. **挂载即拉取**：默认展开后没有「点开」这一动作，原本只在 `toggle()` 里触发的 `load()` 要在挂载时补一次（effect：`open && !payload && !loading → load()`）。折叠后再展开仍走 `toggle` 的同一条惰性路径——`payload` 有缓存就不重复请求。
3. **折叠能力保留**：标题行仍是 toggle，用户可自行收起；本次只改默认态。
4. **弹窗加高度护栏**（本决策的必要配套）：默认展开让 LogDialog 变高，而弹窗此前没有高度上限（`max-w-md` 而已）——矮屏（如 768px 笔记本）会把底部「记录」按钮挤出可视区且无从滚动。给弹窗加 `max-h-[calc(100dvh-2rem)] overflow-y-auto`，仅内容超高时才出现滚动条，收起态无任何变化。
5. **文档同步**：`GenerateScriptPanel` 头注释与 `log-dialog.tsx` 的 ADR 注释标注「默认展开（ADR-0082）」，不让 ADR-0080 的「默认收起」留在代码里误导后来人。

## 被拒方案

- **保持默认收起**（否决）：与用户明示要求相悖；且把闭环的起点藏在一次多余点击之后，ADR-0081 的收益被自己削弱。
- **默认展开且不可折叠**（否决）：去掉 toggle，用户就失去「只想记一条跟进、不看话术」的轻路径——收起态本身有价值，只是不该是默认。
- **默认展开但不加高度护栏**（否决）：矮屏下底部「记录」按钮不可达，等于为了一块可选内容弄丢主操作。展开是目的，不能顺手牺牲主路径可达性。
- **话术区做成弹窗内的独立滚动区**（否决，v1 不做）：双层滚动（弹窗内再套一层）在触控手势上容易互相打架；整窗一根滚动条更简单可靠。
- **直接改 ADR-0080 原文**（否决）：ADR 是不可改写的决策记录，改口会抹掉「当初为什么默认收起」的历史；用新 ADR 承接修订（本文件）更诚实。

## 后果

- 正面：打开「记录跟进」即见话术与『复制话术／打开职位』，闭环从第一眼开始。
- 代价：每次打开弹窗多一次 `/api/followups/scripts` 只读请求（原本用户点开才有）；弹窗初始更高，靠新增的 `max-h` + `overflow-y-auto` 兜住矮屏。
- 边界：话术不可用（模板缺失 / 本行 entry 取不到）时面板照样展开，并安静说一句「暂不可用」——默认展开不改变 ADR-0080 的 fail-closed 语义。
- 回滚：`useState(false)` + 去掉挂载 effect + 撤 `max-h` 即回到 ADR-0080/0081 现状；纯 UI 默认值，无数据迁移。
