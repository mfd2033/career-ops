# ADR-0037: 管道表薪资列以报告的 advertised_comp 为事实源

- **Status:** Accepted (2026-09-17)
- **Context:** 需求（2026-09-17）：「在求职管道页面，除了收件箱之外的页面的列表增加薪资列，支持排序」。现状与约束：

  1. **tracker 行没有任何薪资字段。** `data/applications.md` 的表头是 `# | Date | Company | Role | Score | Status | PDF | Report | Notes | URL`，没有薪资列；`Notes` 是散文（「薪资上限20K低于底线25K」）。逐行唯一**半结构化**的落点是该行评估报告 `## Machine Summary` 的 `advertised_comp`（YAML 围栏内、行首）。
  2. **ADR-0023 决议 5 明文把追踪器表格排除在外**：「作用范围仅收件箱 tab：追踪器表格不动——其薪资来自评估报告研究而非采集卡片，口径不同，不混用」。本次需求正面推翻它，故独立成文（旧 ADR 不改写，新文覆盖，同 ADR-0024 的惯例）。
  3. **实测覆盖率（本机 685 份报告）**：20 份没有 `advertised_comp` 行、157 份字段为 `null`/`~`/空、**508 份有原文**。508 份里 **489 份能解出月薪区间**，19 份解不出（11 条 `not stated`/`not-stated` 家族、4 条 `未公开`/`未显示`/`未注明`/`未标注`、1 条「有竞争力的薪资…」、1 条非人民币（日元）、2 条无区间散文「底薪8100起，综合薪资20000+」）。即 **71%（489/685）的报告有区间，29%（196 份）显示「—」**。
  4. **现成 `parseSalaryText` 直接吃不下报告串**：`10-15K CNY/月`、`8-12K CNY/month`、`8000-15000元/月` 这类币种后缀会撞上它的 `(?![a-zA-Z])` 尾守卫而整体判失败——同一批 508 份有原文的字段，直解只有 **296** 份解出；加一层报告专属归一化后 **489** 份。
  5. **站点口径在报告语境是错层的**：报告里 55 条含「万」有 **22 条是既无 `/月` 也无「年」的裸「万」**（`1.5–2.5万`、`1.5-3万`、`1.2-2万·14薪`…），都是月薪——同一份报告的 D 段把它们写成「1.5–2.5 万/月（15–25K）」。若沿用 `parseSalaryText` 的猎聘口径（裸「万」= 年薪 ÷12），这 22 行会算成 1.25–2.5K，差一个数量级。
  6. **排序实现是共享的**：`pipeline-order.mjs` 里那一个比较器同时喂列表页的 `orderApplications` 与详情页的 `navNeighbors`（ADR-0036）。加排序键必须让两侧拿到**同一份**行数据，否则「列表的顺序」与「下一个走到的位置」会漂——正是 ADR-0036 修过的那类漂移。

- **Scope:** web 层三处——新的薪资解析纯函数、排序比较器的 salary 分支、表格列与 i18n；外加两个页面在服务端 join 薪资事实的落点。**不动**：`parseSalaryText` 与探索页/收件箱/薪资下限（探索页与收件箱消费方共用它，行为由 `web/tests/lib/browser-search.test.mjs` 锁定）、`applications.md` 的 schema 与一切写入路径、CLI 的 `salary-gap.mjs` 与 `data/salary-observations.tsv`、报告 D 段与 Machine Summary 本身的生成。

## Decision

1. **事实源 = 报告 Machine Summary 的 `advertised_comp`，单一字段单一来源。** 不回退报告 `## D) Comp and Demand` 段落（实测与 Machine Summary 会互相矛盾，如 #1040 字段写 `25-55k·15薪` 而 D 段写 not stated），也不回退 `pipeline.md` 的 note 尾段（那是「收件箱薪资」的采集卡片口径，ADR-0023 明令不混）。字段缺失/明确未披露/解析不出 → 一律显示「—」。
2. **新层归一化，复用而不修改 `parseSalaryText`**：新增纯函数模块 `web/src/lib/report-salary.mjs`（普通 `.mjs`，供 `node --test` 直接 import）。规则：先剔非人民币（日元/美元/USD/JPY/欧元/HKD/SGD → 不解析）；去掉括号补充说明（`15-30K CNY（底薪5000-11000+提成…）`）；`CNY|RMB|人民币|￥|¥` 视同「元」；再交 `parseSalaryText(s, "")`（source 传空 = 未知站点口径）。
3. **折算一律月薪口径**：裸「万」= 月薪（×10），只有显式「/年」「年薪」才 ÷12。非人民币一律不解析——报告里作者往往已写好折算注记（如「25万~55万日元/月（约1.2万~2.6万CNY）」），再按汇率算一遍是重复劳动且引入汇率波动。
4. **显示 = 归一化月薪 K 区间**（`10-15K`），字段原文进 `title` 悬停提示；全列只有「区间」与「—」两种形态，与分数列/来源列的空值写法一致（收件箱「原文直出」的先例是采集卡片语境，报告串长得多且带括号补充，直出会撑爆列宽且无法横向比较）。
5. **排序值 = 区间中位值**（与收件箱 ADR-0024 决议 4 同一概念）：中位值降序在前、升序在后；中位值平手回退 **score 降序**，再平手回退 **报告号降序**（完全确定，不依赖 `Array.sort` 的稳定性，与 ADR-0024 的同一取向）。
6. **未披露/无报告的行恒沉底**：不论升序降序都在最后——未知不是一个「很小的薪资」，让它在升序里冒充最低薪会把最该看的行顶到最前。这是对 score/duration 列 `-Infinity` 惯例（升序时未知浮顶）的**有意偏离**，比较器里以「不乘 dir」的方式实现。
7. **排序键 `salary` 加进 `pipeline-order.mjs` 的 SORT_KEYS 与 `pipeline-view.tsx` 的镜像**；默认排序**仍是 score 降序**（不学 ADR-0024 去改默认——本次要求只是「多一列、可排序」，改默认会换掉所有既有 deep link 的默认视图）。报告详情页的上一份/下一份自动继承（同一比较器）。
8. **列插在「分数」之后（第 4 列）**——`SORT_KEYS` 同时驱动表头与单元格顺序，插入即落位。i18n 新键 `pipeline.col.salary`（en `Salary` / zh `薪资`）。
9. **解析在服务端完成，与既有的报告 URL 头读取共用同一次读盘**：`pipelineSummary()` 本就为 score map 逐行读一遍报告（`readApplicationUrl`），薪资事实并入同一次读取，挂在 `Application` 上（沿用 `evalDuration`/`reportVia` 的页面级附加字段惯例）。**不落任何缓存文件、不写 data 目录**——这是推导层，改报告文本即改列值。报告详情页仅在 `sortKey === "salary"` 时才做这次全量 join（其余排序键下薪资不参与顺序，不付这份读盘成本）。

## Alternatives considered

- **回退报告 D 段 / 回退 pipeline.md note 尾段**：覆盖率更高，但前者与 Machine Summary 实测会互相矛盾，后者把采集卡片口径混进同一列（ADR-0023 的原始理由）。
- **原文直出（与收件箱一致）**：列宽被最长的串撑开或频繁截断，`CNY/月`、`元/月` 混排，肉眼无法横向比。
- **按报告 URL 的招聘站点口径折算**：会把这 22 条裸「万」算错一个数量级。
- **非人民币按汇率近似折算**：1 条日元，且报告里已有作者的折算注记。
- **未知行沿用 `-Infinity` 惯例**：列内逻辑与其它数值列一致，但「按薪资从低到高」时最顶上一片是薪资未知的行。
- **默认排序改成按薪资降序**：与收件箱同取向，但会改变所有既有 deep link 与首页统计瓦片跳过来看到的默认列表；用户未要求。
- **给 `applications.md` 加专用薪资列**：动 data contract 与所有写入路径，且历史行需要迁移——ADR-0023 决议 2 已否过一次，理由不变。

## Consequences

- **覆盖率是一个明说的代价**：约 71% 的行显示区间，约 29%（196/685）显示「—」，其原话可在悬停里看到（`not stated`、`未公开`、`底薪8100起，综合薪资20000+` 等）。列不是「每行都有值」的承诺。
- **口径边界**：「报告薪资」= 招聘方挂出来的薪资，**不含**候选人期望/底线，也不与它们做对比。它与「收件箱薪资」（pipeline.md note 尾段的采集卡片口径）是两个概念，见 CONTEXT.md 新增词条——两处不可互推。
- **归一化是推导层**：无迁移、无回填、无第二事实源；改报告里的 `advertised_comp` 即改列值。
- **列表与报告页导航不会漂**：两侧都走 `compareByKey`，详情页在 salary 排序下补齐同一份行数据。
- **已知脆弱点**：括号补充只影响解析、不影响展示（原文在悬停里完整保留）；非人民币一律空（当前 1 条）；`SORT_KEYS` 在 `pipeline-order.mjs` 与 `pipeline-view.tsx` 各有一份，加键须两处同改（既有约定，本 ADR 不新增收敛机制）。
